# Backend demo: internal event registration

Use an authorized development backend with V001–V005 already applied, effective JDBC access,
`SIP_AUTH_ENABLED=true`, and the existing database-capable profile. Follow the
[V005 operator procedure](../backend/EVENT_REGISTRATIONS.md#manual-supabase-application-operator-only)
before deployment. Never rerun applied migrations. This walkthrough creates demo records only when
an operator executes it; the coding agent has not contacted Supabase or deployed anything.

Use a private terminal or Postman environment. Do not record real tokens/passwords, use shell
tracing, or enable HTTP/header/body debug logs. All values below are placeholders. In Postman,
use the same methods, URLs, Bearer authentication, and JSON bodies; save response IDs as variables.

1. Obtain an existing authenticated OWNER account. Use the current login endpoint:

   ```sh
   BASE='http://127.0.0.1:8080' # or the authorized development Render HTTPS origin
   curl -sS -X POST "$BASE/api/auth/login" -H 'Content-Type: application/json' \
     --data '{"email":"OWNER_EMAIL","password":"OWNER_PASSWORD"}'
   ```

   Expect 200. Privately copy `session.accessToken` into `OWNER_TOKEN` below. Verify the persisted
   organization association and OWNER role with profile:

   ```sh
   OWNER_TOKEN='OWNER_ACCESS_TOKEN'
   curl -i "$BASE/api/users/me" -H "Authorization: Bearer $OWNER_TOKEN"
   ```

   Expect `organizationRole:"OWNER"` and a nonnull organizationId. If an authorized demo account
   has no organization, create one through the existing API (201) and fetch profile again:

   ```sh
   curl -i -X POST "$BASE/api/organizations" -H "Authorization: Bearer $OWNER_TOKEN" \
     -H 'Content-Type: application/json' \
     --data '{"name":"Demo Volunteers","description":"Backend demonstration","website":"https://example.org"}'
   ```

   Do not create another organization for an already associated account.

2. Publish an INTERNAL opportunity. Replace these illustrative dates with dates strictly in the
   future at demo time, with end after start. Server time decides eligibility.

   ```sh
   curl -i -X POST "$BASE/api/organizations/me/opportunities" \
     -H "Authorization: Bearer $OWNER_TOKEN" -H 'Content-Type: application/json' \
     --data '{"title":"Demo park cleanup","description":"Help clean an Atlanta park","location":"Atlanta","eventStart":"2027-01-16T14:00:00Z","eventEnd":"2027-01-16T17:00:00Z","registrationType":"INTERNAL","registrationUrl":null}'
   ```

   Expect 201; copy response `id` as EVENT_ID. Response creatorId/organizationId derive from OWNER.

   ```sh
   EVENT_ID='INTERNAL_EVENT_UUID'
   ```

3. Obtain a separate registered volunteer account through existing signup/login. For an existing
   account:

   ```sh
   curl -sS -X POST "$BASE/api/auth/login" -H 'Content-Type: application/json' \
     --data '{"email":"VOLUNTEER_EMAIL","password":"VOLUNTEER_PASSWORD"}'
   VOLUNTEER_TOKEN='VOLUNTEER_ACCESS_TOKEN'
   curl -i "$BASE/api/users/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
   ```

   Expect 200 and a different user ID. Ordinary STANDARD with no organization association works.
   OWNER and ADMIN also retain volunteer registration rights.

4. Register the volunteer, with no request body:

   ```sh
   curl -i -X POST "$BASE/api/opportunities/$EVENT_ID/registrations/me" \
     -H "Authorization: Bearer $VOLUNTEER_TOKEN"
   ```

5. Verify HTTP 201, `Cache-Control: no-store`, and this response shape:

   ```json
   {"id":"REGISTRATION_UUID","eventId":"INTERNAL_EVENT_UUID","userId":"VOLUNTEER_UUID","registeredAt":"2026-11-16T18:00:00Z"}
   ```

   Actual UUID/time values are generated by PostgreSQL. userId must match the volunteer, not OWNER.

6. Retrieve registration status and the volunteer's paginated registrations:

   ```sh
   curl -i "$BASE/api/opportunities/$EVENT_ID/registrations/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
   curl -i "$BASE/api/users/me/registrations?page=0&size=20" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
   ```

   Expect 200, `registered:true` and the same registration ID. The personal page includes event
   title, organizationId, start/end, location and registeredAt.

7. Repeat the registration request:

   ```sh
   curl -i -X POST "$BASE/api/opportunities/$EVENT_ID/registrations/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
   ```

   Expect 409 with `code:"ALREADY_REGISTERED"`. The original row remains; no duplicate is inserted.

8. Retrieve the organization's attendees as OWNER:

   ```sh
   curl -i "$BASE/api/organizations/me/opportunities/$EVENT_ID/registrations?page=0&size=20" \
     -H "Authorization: Bearer $OWNER_TOKEN"
   ```

   Expect 200, an item with the volunteer's userId, first/last name, registration ID/timestamp,
   and no email. A same-organization ADMIN token works; a volunteer or another organization's
   manager gets 403. An event with zero registrations has `items:[]`.

9. Cancel as the volunteer, with no body:

   ```sh
   curl -i -X DELETE "$BASE/api/opportunities/$EVENT_ID/registrations/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
   ```

   Expect 204 and no response body. The event and other volunteers' rows remain.

10. Check status again:

    ```sh
    curl -i "$BASE/api/opportunities/$EVENT_ID/registrations/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
    ```

    Expect `{"eventId":"INTERNAL_EVENT_UUID","registered":false,"registration":null}`.
    Repeated DELETE before start returns 404 REGISTRATION_NOT_FOUND. Another POST before start
    creates a fresh registration (201). At/after start POST/DELETE return 400 EVENT_ALREADY_STARTED.

11. Publish EXTERNAL and prove it rejects internal registration:

    ```sh
    curl -i -X POST "$BASE/api/organizations/me/opportunities" \
      -H "Authorization: Bearer $OWNER_TOKEN" -H 'Content-Type: application/json' \
      --data '{"title":"Demo external signup","description":"Register with the provider","location":"Atlanta","eventStart":"2027-01-17T14:00:00Z","eventEnd":"2027-01-17T17:00:00Z","registrationType":"EXTERNAL","registrationUrl":"https://example.org/register"}'
    EXTERNAL_EVENT_ID='EXTERNAL_EVENT_UUID'
    curl -i -X POST "$BASE/api/opportunities/$EXTERNAL_EVENT_ID/registrations/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
    curl -i "$BASE/api/opportunities/$EXTERNAL_EVENT_ID/registrations/me" -H "Authorization: Bearer $VOLUNTEER_TOKEN"
    ```

    Expect publish 201, registration 400 INTERNAL_REGISTRATION_REQUIRED, and status 200/false.
    The frontend later uses the external registrationUrl; opening that URL never writes an internal row.

Read-only SQL check in the intended Supabase project (operator only): run after step 5/8 to see
one row, after step 10 to see none, and after step 11 to confirm none for EXTERNAL. Replace the
quoted UUID placeholder with a real event UUID. No emails, tokens or passwords are selected.

```sql
SELECT r.id AS registration_id, r.event_id, r.user_id, e.title,
       e.registration_type, e.organization_id, e.event_start, r.registered_at
FROM public.event_registrations r
JOIN public.events e ON e.id = r.event_id
WHERE r.event_id = 'EVENT_UUID'::uuid
ORDER BY r.registered_at, r.id;

SELECT event_id, user_id, count(*)
FROM public.event_registrations
GROUP BY event_id, user_id HAVING count(*) > 1;
-- Expect zero duplicate groups.
```

Do not use privileged SQL to bypass registration rules or delete demo events/accounts referenced by
NO ACTION FKs. Use the cancellation API to remove demo registrations before start. There is no event
or account deletion feature in this task. Keep valid demo dates and current access tokens ready;
refresh/login again on 401. A health check alone does not verify Auth, JDBC permissions or RLS.
